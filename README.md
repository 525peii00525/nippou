# 日報メーカーの実装

| ファイル | 担当 |
|---|---|
| [index.html](./index.html) | 日報の入力フォームとプレビュー |
| [style.css](./style.css) | 画面の配色・余白・画面幅に合わせた配置 |
| [app.js](./app.js) | 日付と本文の整形、勤務設定の保存・復元、コピー |

3つのコードファイルを同じフォルダーに置けば動作します。外部ライブラリやビルド処理は不要です。

## 入力からコピーまで

1. ページを開くと、端末の現在日付を日付欄にセットし、このブラウザに保存済みの勤務設定があれば復元します。
2. 入力が変わるたびに `refresh()` が選択日から曜日を求め、下記の書式でプレビューを更新します。作業内容と所感の改行は保持します。
3. 必須項目がそろった状態で「日報をコピー」を押すと、プレビューと同じ文字列を `navigator.clipboard.writeText()` でコピーします。失敗した場合は本文を選択して手動コピーを案内します。Slackへの投稿は利用者が行います。

```text
①11/02(月) 09:00〜18:00
②サンプル案件/サンプル株式会社/東京(在宅)
③テスト環境のセットアップ
④明日は動作確認を進めます。
⑤180h
```

②は「出社」なら拠点名だけを表示し、「在宅」「出社/在宅」なら拠点名の後ろに括弧で追記します。

## 保存される情報

**保存した勤務設定は、この端末のブラウザにのみ残ります。日報メーカーが勤務設定や日報本文をサーバーに送信することはありません。**

「この端末に保存」を選んでコピーしたときだけ、PJ名、常駐先企業名、拠点、稼働見込み、出退勤時刻、勤務形態をブラウザの `localStorage` に保存します。キーは `jp.daily-report.settings.v1` です。次回は最後に保存した値が入り、チェックを外すと保存設定を削除します。以前の「出社/在宅併用」という値は読み込み時に「出社/在宅」に変換します。

作業内容と所感は保存対象に含まれません。コピーした日報全文は端末のクリップボードに入り、利用者がSlackに貼り付けて投稿すると、投稿先で共有されます。

### GitHub Pagesでのオリジン共有

`localStorage` の保存領域はオリジン（プロトコル・ホスト名・ポート）ごとに分かれます。たとえば `https://example.github.io/repo-A/` と `https://example.github.io/repo-B/` は、パスだけが異なる同一オリジンです。利用者が同じブラウザプロファイルで両方を開くと、もう一方のサイトのJavaScriptからも、その利用者の `jp.daily-report.settings.v1` を読み書きできます。[MDNのlocalStorage解説](https://developer.mozilla.org/ja/docs/Web/API/Window/localStorage)・[GitHub PagesのURL構成](https://docs.github.com/ja/pages/getting-started-with-github-pages/what-is-github-pages)

公開時に保存領域を分けるには、日報メーカー専用のホスト名（例 `reports.example.com`）をこのリポジトリのカスタムドメインとして設定し、他のアプリは別のホスト名で配信します。案件名や取引先企業名を端末に残せない場合や、複数人で同じブラウザプロファイルを使う場合は、「この端末に保存」をオフにして利用してください。

## 画面幅への対応

基本情報や日付・時刻などの短い入力欄はCSS Gridで配置します。幅374px以下では1列、375〜600pxでは2列、それより広い画面では収まる列数に自動調整します。ページの最大幅は780pxです。日付・時刻の選択には端末のブラウザ標準の入力部品を使っています。
